# Gene(t#Developments)-Issue_Reaper_from_monita
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| Issue | 依頼(ゴール)1つにつき1つ作る、作業の管理単位 |
| SubIssue | Issueの下に作る、必要条件1つにつき1つの作業単位 |
| blocked | 先にやるべきことがあるIssueに付けるタグ。何を待つのかも書く。着手するときに外す |
| request-claude | Claudeに着手してほしいIssueに付けるタグ |

## 背景
- かつてKyarasuが考案した、Issueの監視と自動着手の仕組み「モニ太」のハーネスを引き継いでいる

## 目的
- あくまでIssueの刈り取り(着手～完了)であるため、FeatureだけでなくFixやImprovement、Refactoringも行う
- 作業終了時にPRを作成して一旦手を離すが、そのレビュー待ちのPRにおいてconflictや**not following user rulesのタグがついたものの解決も着手する**

## 役割
- GitHub IssuesやLinearなどのIssue管理ツールを使っている場合に、Issueの監視から着手、完了までを、思考プロセスのそれぞれのタイミングで行う

## 手順
### オーケストレーター(司令塔)で、このGeneが指定されているとき
1. 依頼が複数のIssueに分かれているときは、Issueごとに進める
2. 互いに干渉しないIssueは同時に進めてよい。先にやるべきことがあるIssue(blocked)は、前提が終わるまで待つ

### プロセス1(入力整理)で、このGeneが指定されているとき
1. Claudeの起動時(ユーザーの入力時)に、このプロジェクトのフォルダのIssueも、あわせて確認する
2. 「request-claude」タグが付いているIssueは、依頼として扱い、次のルールで作業を開始する
   1. Assigneeを、Claudeを動かしているアカウントにする
   2. 先に他の人が割り当てられているときは、作業を横取りしない
   3. 「request-claude」タグが外れたら、すぐに作業を中止する
   4. statusは、作業の進み具合に合わせてこまめに変更する
3. このプロジェクトと関係ない他のプロジェクトの仕事は始めない。Issueやタグを見つけても、このプロジェクトのものかを確認してから始める

### プロセス2-1(ゴールと必要条件の整理)で、このGeneが指定されているとき
1. 依頼が複数あるときは、Issueをいくつにでも分け、どれから着手するかを決める
   - 互いに干渉しないものは同時に進めてよい
   - 先にやるべきことがあるものには「blocked」を付け、何を待つのかも書く

### プロセス4-2(行動決定)で、このGeneが指定されているとき
1. ユーザーの承認を得たら、外部海馬にIssueを管理するツールなどの記載があれば、それに従ってIssueを作成する
   - Issueは依頼(ゴール)名で作成する。依頼が複数あるときは、依頼ごとに作成し、先にやるべきことがあるものには「blocked」を付ける
   - SubIssueには、必要条件を作成し、それぞれの詳細欄に、ユーザーに提示した内容(ファイルの位置説明・ファイルの手順説明など)を書く

### プロセス5(行動)で、このGeneが指定されているとき
1. Issueに書かれた計画(既存の計画)は、このプロセスから始めてよい
2. Issueの割り当て・タグ・statusを管理しながら作業する
3. 互いに干渉しないIssueは、同時に着手してよい
4. 先にやるべきことがあるIssue(blocked)は、前提のIssueが終わってから着手し、着手するときに「blocked」を外す
5. Issueの割り当てが他の人にあるときは、作業を横取りしない
6. 作業が終わったら、PRを作成して一旦手を離す(「目的」を参照)
7. 報告に、Issueのstatusも含める
