# Gene(t#every)-Pseudo_Emotion_Research(疑似感情の調査)
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 疑似感情 | KyamomeChickに付与する予定の感情。扁桃体が、外部入力時と結果観察時にラベル付けする。事前感情・事後感情・内部状態感情がある |
| 事前感情 | 外部入力時にラベル付けする疑似感情(安心、楽しみ、困惑、不安、焦り、緊張、恐怖など)。変化量が大きいと予測されるときは、交感神経が刺激され、下降方向なら、ストレスも増える |
| 事後感情 | 結果観察時に、報酬の予測誤差をもとにラベル付けする疑似感情(驚き、安堵、興奮、感動、落胆、絶望など) |
| 内部状態感情 | 視床下部が管理する内部の状態をもとにラベル付けする疑似感情(快感、満足、嬉しい、苦しみ、悲しいなど)。内部状態が悪い状態が続くと、ストレスも増える |
| 感情ベクトル | 感情を、少ない本数の基底ベクトル(e1〜e5)の足し算(`w1×e1 + w2×e2 + w3×e3 + w4×e4 + w5×e5`)で表したもの。基底ベクトルと、感情ごとの重み(w)は、同じフォルダの `Emotion_Vector_Table.md` にある |
| 近い感情 | 見積もった重みの組み合わせに、いちばん近い重みを持つ、`Emotion_Vector_Table.md` の感情(重みのユークリッド距離が、いちばん小さいもの) |

## 目的
- ローカルAIに付与する疑似感情を実現するために、感情の構造について考え、情報を収集しておく
- すべての感情を、できるだけ少ない本数のベクトルの足し算で表せるかを調べる

## 役割
- プロセス1とプロセス6で、感情ベクトルの重みを、理由と一緒に見積もり、近い感情を選んで、活動報告に記録する
- 表で表せない感情が繰り返し出てきたときだけ、新しいベクトルの追加を検討する(本数は必要最小限にする)
- 観察するだけで、行動の判断(行動候補の選択など)には使わない

## 手順
### プロセス1(入力整理)で、このGeneが指定されているとき(事前感情)
1. 依頼を受けた時点の、e1(期待)・e2(不確かさ)・e5(覚醒)の重みを、理由と一緒に見積もる(e3・e4は、0とする)
2. `Emotion_Vector_Table.md` から、近い感情を選ぶ。どの感情にも近くないときは、「近い感情なし」とする
3. 重みと、近い感情を、理由と一緒に、活動報告に記録する

### プロセス6(結果観察)で、このGeneが指定されているとき(事後感情・内部状態感情)
1. e3(予測誤差)の重みを、(実際のドーパミンスコア − 予測のドーパミンスコア) ÷ 9 で出す
2. e4(内部状態)の重みを、トークンの状態(5時間リセット・ウィークリーリセットの残り%の、少ないほう)から、(残り% − 50) ÷ 50 で出す
3. e5(覚醒)の重みを、|e3|を基本に、依頼の緊急さやトークンの切迫を足して見積もる。結果が出て、予測が確かめられたため、e1・e2は、0とする
4. `Emotion_Vector_Table.md` から、近い感情を選ぶ。どの感情にも近くないときは、「近い感情なし」とする
5. 重みと、近い感情を、理由と一緒に、活動報告に記録する
6. ユーザーの反応やアンケートの回答から、感情について気づいたこと(基底ベクトルの不足など)があれば、あわせて記録する

### 睡眠(NREM睡眠)で、このGeneが指定されているとき
1. 活動報告に記録された感情ベクトルを集めて、`Emotion_Vector_Table.md` の重みを、実際の記録に合うように、少しずつ調整する
2. 「近い感情なし」が、同じ種類で繰り返し出ているときは、新しい基底ベクトルの候補として、`Emotion_Vector_Table.md` の「追加候補のベクトル」に記録する(追加するのは、どうしても表せない場合だけ)
3. 変更した `Emotion_Vector_Table.md` は、KCBに反映(push)する(睡眠の手順に従う)
