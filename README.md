# KyamomeChick Brain-Inspired Harness

## 概要
ClaudeなどのクラウドAIに、「依頼を受ける → 計画する → 実行する → 振り返る → 睡眠で記憶を整理する」という流れを、人間の脳の構造に着想を得た手順書で、守らせるためのハーネス(手順書と記憶の置き場の集まり)。

- 3つの思考: ユーザーの依頼に答える有起点思考、ユーザーの入力がないときの無起点思考、記憶を整理する睡眠(NREM・REM)
- 計画してから実行する: 依頼を、ゴールと必要条件に分け、複数の行動候補を評価して、ユーザーの承認を得てから、実行する
- 予測と結果のずれから学ぶ: 行動前に報酬(ドーパミンスコア)を予測し、結果との差を、反省と睡眠で、経験として蓄える
- 追加の動き(Gene)を差し込める: 依頼のタグ付け、Issueの自動着手、疑似感情の調査など
- 記憶は、公開しない: 手順書だけを公開し、記憶は、非公開の場所に置ける

English: A brain-inspired harness (a set of procedures and a memory layout) for cloud AI agents such as Claude. It adds trigger-based thinking, non-trigger thinking, and sleep-based memory consolidation. Experimental, and not affiliated with Anthropic.
## このプロジェクトの定義
このプロジェクトはClaudeなどのクラウドAIに適用するハーネスであり、
KyamomeChickという、Kyarasuが育てているローカルAIの脳構造に基づいている。

人間は、下の「目的」と「役割」の2つを読めば、このプロジェクトの概要がだいたい理解できる。
詳細は、`1-Processes/` の各プロセスの手順書に書いてある。

## 目的
プロダクトの開発において、クラウドAIに作業させる際、以下の点を満たすためにこのハーネスを準備した。
- ユーザーが冗長な指示をしても、取りこぼさず作業を行う
- クラウドAIが作業した後、ユーザーがその作業を追うことができる
- クラウドAIのアカウントが変わり、コンテキストがすべてリセットされても、プロダクトの作業を続行できる
- トークン消費を抑える
- ユーザーとクラウドAIの価値観の差で齟齬が発生した場合は、その事例を学習し、次回以降の活動でその改善を反映できる
- ユーザーのルールを参照し、遵守して開発を進めることができる

## 役割
上の目的を、人間の脳の構造(神経解剖学)に基づく、次の方法で解決している。

| 目的 | 解決する方法(担当する脳の部位) |
| --- | --- |
| 冗長な指示を取りこぼさない | 連合皮質が入力を網羅率100%のまま整理し(プロセス1)、背外側前頭前皮質(DLPFC)が依頼を最小単位に分けて、ゴールと必要条件を決める(プロセス2-1) |
| ユーザーが作業を追える | 司令塔(オーケストレーター)が、プロセスごとにユーザーへ報告して活動報告を更新する。行動前には、ファイルの位置説明とファイルの手順説明を提示して、承認を得る(プロセス4-2)。結果観察では、必要条件を満たしてゴールを実現できたかを確認する(プロセス6) |
| コンテキストがリセットされても続行できる | meeting-roomに、有起点の活動報告・固有のルール・planを置き、KCBの海馬に、プロダクトをまたいで使える記憶(ユーザーの資料やルール、経験)を入れる(睡眠)。別のAIがそれを読めば、作業を再開できる |
| トークン消費を抑える | 前帯状皮質(ACC)が、作業に見合うモデル・検索の深さ・思考量(努力量)を決める(プロセス2-2)。トークンを多く使う作業は、軽いモデルのサブエージェントに任せる。視床下部が、トークンの使用状況を記録して、消費の目安を作る(プロセス1・6) |
| 価値観の差の齟齬を学習して反映する | 腹側被蓋野(VTA)が、行動前に報酬を予測し(プロセス4-2)、結果観察で実際の報酬との予測誤差を出す(プロセス6)。反省・記憶更新で次回に使える経験にして活動報告に記録し(プロセス7)、睡眠(NREM睡眠・REM睡眠)で経験を整理して、KCBの記憶に入れる |
| ユーザーのルールを参照して遵守する | 外部海馬のユーザーのルールを、情報の統合(プロセス3)で参照し、サブエージェントへの指示に含め(プロセス5)、結果観察でルールへの則りを調べる(プロセス6) |

あわせて、ユーザーの入力がないときにも、知識や反省を蓄える無起点思考プロセスがある。

## 環境の分け方(meeting-room・KCB)
外界的な環境(各プロダクト側)と、脳内的な環境(KCB)に分ける。

| 環境 | 説明 |
| --- | --- |
| meeting-room | 外界的な環境。各プロダクトに置く、開発するクラウドAIと人間が、プロダクトのプログラムとは関係なく、認識を合わせる場。有起点の活動報告、そのプロダクト固有のルール、planを置く。睡眠プロセスは、meeting-roomの上で行う。雛形は、`5-Meeting_Room/` にある |
| KCB | 脳内的な環境。このプロジェクト。思考プロセスの手順書、DNAs、海馬(プロダクトをまたいで使える記憶)、視床下部(トークンの状態)を持つ |

ルール
- そのプロダクト固有のもの(有起点の活動報告・固有のルール・plan)は、meeting-roomに置き、KCBには置かない
- 無起点の活動報告と夢日記は、プロダクトに依存しないため、KCBの海馬(`2-Internal_Hippocampus/`)に直接置く
- planは、2種類に分ける。プロダクトの設計変更の計画は、meeting-roomの `plans/` に置く。クラウドAI自身の、できる幅を広げる計画は、KCBの海馬の `Growth_Plans/` に置く
- プロダクトをまたいで使える記憶(Experiences、一般化した教訓、既知パターン、ユーザーの好みなど)は、KCBの海馬に置く
- meeting-roomからKCBの記憶への登録は、meeting-roomの上で行う睡眠プロセスだけが行う。睡眠で、他のプロダクトでも使えるものを選別して入れる
- ユーザーのルール(`user-rules.md`)は、KCBの外部海馬に置く

## Claudeへの反映の仕方
このリポジトリは、手順書の集まりで、Claudeに読ませて初めて動く。Claude Codeで使う場合の手順は、次のとおり

1. KCB(このリポジトリ)を、手元にcloneする
2. 使うプロダクトに、meeting-roomを置く。雛形は、`5-Meeting_Room/`(中身を、そのプロダクトのmeeting-roomとしてコピーする)
3. Claudeに読ませる。プロダクトの `CLAUDE.md`(または、ユーザー全体の `~/.claude/CLAUDE.md`)に、次のように書く
   ```text
   # KCB(KyamomeChickBrain-Inspired-Harness)に従う
   - ユーザーの入力を受けたら、まず <KCBのパス>/1-Processes/1-Trigger_Based_Thinking_Process/0-Orchestrator.md を読み、その手順に従う
   - このプロダクトのmeeting-roomは、<meeting-roomのパス>
   - <KCBのパス>/3-Hippocampus/ATTENTION.md がある場合は、先に読む
   ```
4. 各プロセスの手順書は、そのプロセスに進むときに読む(最初に全部は読まない。トークンを節約するため)
5. 記憶を、公開リポジトリに置きたくない場合は、`3-Hippocampus/ATTENTION.md`(`.gitignore` で除外される)に、「記憶は、非公開の場所(例: 別の非公開リポジトリ)に、同じフォルダ構造で置く」と、置き場所を書く
6. 無起点思考や、Issue_Reaperの1分ごとの確認は、定期的に動かす仕組み(例: Claude Codeの `/loop`、cron)で起動する
7. Geneは、`2-DNAs/` のGeneを、Request_Sorterが、依頼のタグに合わせて指定する。使いたくないGeneは、名前の条件の文字を `x` にする(例: `Gene(x#every)-Name`)

注意
- 手順書は、Claudeへの指示で、強制する仕組みではない。実際に従うかは、`CLAUDE.md` の読み込みと、モデルの判断による
- このハーネスは、まだ実運用で通して検証していない。重みや数値(感情ベクトルなど)は、初期値
