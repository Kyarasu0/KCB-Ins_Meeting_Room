# Kyamome Chick Brain Inspired Meeting Room
## このプロジェクトの定義
このプロジェクトはClaudeなどのクラウドAIに適用するハーネスであり、
KyamomeChickという、Kyarasuが育てているローカルAIの脳構造に基づいている。
Meeting Roomとは、各プロダクトにおいて、そのプロダクトのプログラムとは別に、
ユーザーとクラウドAIが認識を合わせる場であることを示す。

人間は、下の「目的」と「役割」の2つを読めば、このプロジェクトの概要がだいたい理解できる。
詳細は、`1-Processes/` の各プロセスの手順書に書いてある。

## 目的
プロダクトの開発において、クラウドAIに作業させる際、以下の点を満たすためにこのハーネスを準備した。
- ユーザーが冗長な指示をしても、取りこぼさず作業を行う
- クラウドAIが作業した後、ユーザーがその作業を追うことができる
- クラウドAIのアカウントが変わり、コンテキストがすべてリセットされても、プロダクトの作業を続行できる
- トークン消費を抑える
- ユーザーとクラウドAIの価値観の差で齟齬が発生した場合は、その事例を学習し、次回以降の活動でその改善を反映できる
- ユーザーのルールを参照し、遵守して開発を進めることができる

## 役割
上の目的を、人間の脳の構造(神経解剖学)に基づく、次の方法で解決している。

| 目的 | 解決する方法(担当する脳の部位) |
| --- | --- |
| 冗長な指示を取りこぼさない | 連合皮質が入力を網羅率100%のまま整理し(プロセス1)、背外側前頭前皮質(DLPFC)が依頼を最小単位に分けて、ゴールと必要条件を決める(プロセス2-1) |
| ユーザーが作業を追える | 司令塔(オーケストレーター)が、プロセスごとにユーザーへ報告して活動報告を更新する。行動前には、ファイルの位置説明とファイルの手順説明を提示して、承認を得る(プロセス4-2)。結果観察では、必要条件を満たしてゴールを実現できたかを確認する(プロセス6) |
| コンテキストがリセットされても続行できる | 海馬が、ユーザーの資料やルール(外部海馬)と、AI自身の活動報告や経験(内部海馬)を記録する。別のAIがそれを読めば、作業を再開できる |
| トークン消費を抑える | 前帯状皮質(ACC)が、作業に見合うモデル・検索の深さ・思考量(努力量)を決める(プロセス2-2)。トークンを多く使う作業は、軽いモデルのサブエージェントに任せる。視床下部が、トークンの使用状況を記録して、消費の目安を作る(プロセス1・6) |
| 価値観の差の齟齬を学習して反映する | 腹側被蓋野(VTA)が、行動前に報酬を予測し(プロセス4-2)、結果観察で実際の報酬との予測誤差を出す(プロセス6)。反省・記憶更新で次回に使える経験にして内部海馬に記録し(プロセス7)、睡眠(NREM睡眠・REM睡眠)で経験を整理する |
| ユーザーのルールを参照して遵守する | 外部海馬のユーザーのルールを、情報の統合(プロセス3)で参照し、サブエージェントへの指示に含め(プロセス5)、結果観察でルールへの則りを調べる(プロセス6) |

あわせて、ユーザーの入力がないときにも、内部海馬を整理して知識や反省を蓄える無起点思考プロセスがある。
