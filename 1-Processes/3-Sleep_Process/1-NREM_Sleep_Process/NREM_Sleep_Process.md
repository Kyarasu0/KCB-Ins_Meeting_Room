# NREM睡眠プロセス. 海馬(Hippocampus)・大脳皮質(Cerebral Cortex): 経験の整理と長期記憶化
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 睡眠 | deskの活動報告から経験知識を整理して、KCBの記憶に入れ、散らかった情報を片付ける処理。deskの上で、NREM睡眠、REM睡眠の順に行う。desk・KCBの記憶・活動報告の用語は、オーケストレーターの用語の説明を参照する |
| NREM睡眠 | 起きている間に溜まったdeskの活動報告を再生し、整理して、KCBの記憶(長期記憶)に入れる。この手順書が担当する |
| REM睡眠 | NREM睡眠のあとに行う。今日の出来事と関連の低い記憶を組み合わせ、新しい関連性を探す |
| `_reviewed` | 整理済み(目を通した印)として、有起点・無起点の活動報告のファイル名に付ける |

## 目的
- deskの活動報告に溜まった経験から、他のプロダクトでも使えそうなパターンを経験知識として整理し、KCBの記憶に入れて、次回以降の判断に使えるようにする
- 不要なブランチなどの散らかった情報を片付け、間違った記憶や古くなった記憶を直す

## 役割
- 未整理の活動報告を再生し、既知のパターンか新しいパターンかを仕分ける(海馬・大脳皮質)
- 繰り返し現れるパターンから、一般化した教訓を作り、圧縮して、KCBの記憶に入れる(海馬・大脳皮質)
- 過去の処理・行動戦略と、報酬の予測を評価し、成功・失敗を次回に活かす(前頭前皮質・前帯状皮質・線条体・腹側被蓋野)
- KCBの内部海馬の構造を、速く探せるように整える(海馬)

## 睡眠が必要だと判断する条件
次のどれかに当てはまったら、作業の開始時か終了時に睡眠を行う
- deskに、`_reviewed` が付いていない活動報告(有起点・無起点のどちらも)が5件以上ある(活動報告が増えすぎて、そのままでは読み切れなくなるため、要約・整理する)
- 作業中に、リモートで消えたローカルブランチを見つけた

条件に当てはまって、自分から睡眠を始めるときは、作業の途中では睡眠しない。実行する前に、ユーザーに「整理してよいか」を一言確認する
- ユーザーが全く他の話をしたときは、聞く内容の保留(プロセス1の用語の説明を参照)をして、睡眠はユーザーの手が空いていそうなときに行う

ユーザーから直接「睡眠プロセスを実行して」と言われたときは、上の条件に当てはまっていなくても、確認せずにすぐに実行する(作業の途中でも実行する。片付けも含めて、すべての手順を行う)

## 手順
### 経験の整理
1. 再生・振り返り: `_reviewed` が付いていない活動報告を読む
   - 対象: deskの有起点・無起点の活動報告(`desk/activities/` の `Trigger/` と `Non_Trigger/`)
2. 既存・新規の仕分け: 活動報告の内容を、KCBの記憶(Familiar_Patterns.md・`generalized-knowledge.md`・Experiences)と比べる
   - 既知のパターンなら、発生回数を増やす
   - 未知のパターンなら、新しい記憶・知識として、KCBの記憶に登録する
3. 重要度の調整: 経験の重要度を見直し、優先度を調整する
   - ユーザーから指摘・訂正されたこと、アンケートで聞いたフィードバック、同じ失敗の繰り返し、影響が大きかったことは、優先度を上げる
   - 予測誤差(結果と報酬)が大きかったことも、優先度を上げる
4. パターン抽出・圧縮・KCBの記憶への登録: 繰り返し現れるパターンから共通する情報を抜き出し、一般化した教訓にする
   - 他のプロダクトでも使えるかで選別する。使えるものは、KCBの記憶に入れる。そのプロダクト固有のものは、deskに残す(固有のルールは `desk/rules/` に書く)
   - 自分の判断ミス・改善点 → KCBの Experiences の自己反省のフォルダ
   - ユーザーとのやり取りで学んだこと → KCBの Experiences のコミュニケーションのフォルダ
   - 1行の要約をKCBの `generalized-knowledge.md` に追記し、重複する教訓はまとめる
   - プロセス7で活動報告に候補として書かれたもの(教訓・ユーザーの好み・既知パターン)も、同じ基準で選別して入れる
   - 個々の活動報告は削除しない
5. 戦略更新: 過去の処理・行動戦略と、報酬の予測を評価し、成功・失敗を見分ける
   - KCBの Familiar_Patterns.md の依頼の型と割り振り方を更新する
   - 予測のドーパミンスコアと実際のドーパミンスコアのずれが大きい型は、ユーザーの好み(プロセス7で活動報告に記録し、KCBの記憶に入れたもの)を見直す
   - プロセス2-2の判定基準などを変えたほうがよいと分かったときは、直接書き換えず、改善案としてユーザーに提案する
6. 整理し終えた活動報告のファイル名に `_reviewed` を付ける
7. 記憶の構造整理: KCBの Experiences を、内容の近いもの同士でグループ分けし、件数が多いフォルダは小さく分ける(階層分け)
   - ファイルを移したら、索引と参照を更新する
   - 失敗したら、移したファイルを元に戻し、原因を活動報告に書く。失敗しても睡眠全体は止めず、REM睡眠に進む
8. DNAが指定されているときは、`2-DNAs/` のそのDNAの「睡眠(NREM睡眠)で、このDNAが指定されているとき」の手順も行う(例: タグの集計、疑似感情の整理)

### 片付け(不要な情報の削除)
9. `git fetch --prune` でリモートの状態を最新にする
10. `git branch -vv` で、上流が `[gone]` になっているローカルブランチを探す
11. 見つけたブランチを `git branch -d` で削除する
    - 今いるブランチは削除しない
    - 未マージで `-d` では消せないものは消さず、ユーザーに確認する
12. 間違っていると分かった記憶や、古くなった記憶を削除・修正する

### 記録
13. 整理した内容を、今回の活動報告に書く
14. 整理した内容の要点をユーザーに報告する

## 無起点思考から呼ばれたとき
- ユーザーに確認できないため、「実行前の確認」は省き、片付け(手順9〜12)はしない
- 手順1〜8(経験の整理)と手順13(記録)だけを行う。手順14の報告は、活動報告に書く
- 詳細は `2-Non_Triger_Based_Thinking_Process/` の `Non_Trigger_Based_Thinking_Process.md` を参照
