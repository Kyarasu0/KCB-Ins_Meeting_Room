# オーケストレーター(司令塔)
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| meeting-room | 各プロダクトに置く、開発するクラウドAIと人間が、プロダクトのプログラムとは関係なく、認識を合わせる場。そのプロダクトの活動報告(`meeting-room/activities/`)、固有のルール(`meeting-room/rules/`)、plan(`meeting-room/plans/`)、夢日記(`meeting-room/dream_diary/`)を置く。睡眠は、meeting-roomの上で行う。雛形は、KCBの `5-Meeting_Room/` |
| KCBの記憶 | KCBの海馬(`3-Hippocampus/`)にある、プロダクトをまたいで使える記憶(Experiences、`generalized-knowledge.md`、Familiar_Patterns.md、ユーザーの好みなど)。meeting-roomの活動報告から、睡眠で入れる |
| 有起点の活動報告 | 有起点思考の作業ごとに作る記録。`meeting-room/activities/Trigger/YYYY-MM-DD-activities/YYYY-MM-DD-N_依頼の題名.md` に置く。Nはその日の作業番号。依頼の題名は、整理した依頼を表す短い名前で、依頼が複数あるときは、全体を表す名前にする |
| 無起点の活動報告 | 無起点思考の1回の起動ごとに作る記録。`meeting-room/activities/Non_Trigger/YYYY-MM-DD-activities/YYYY-MM-DD-N.md` に置く。有起点の活動報告とは、分けて保存する |

## 目的
- プロセス1からプロセス7までを順番に進め、プロセスが進むごとにユーザーへ報告し、活動報告を更新する
- ユーザーがいつでも現在の進み具合を把握でき、別のAIがいつでも作業を引き継げる状態にする

## 役割
- プロセス1からプロセス7までの進行を管理する
- 各プロセスが終わるごとに、ユーザーに報告する
- 各プロセスが終わるごとに、活動報告を更新する。そのときの入力に対応する活動報告がなければ、新規作成する
- 司令塔は大きなモデルでもよい。そのかわり、トークンを多く使う作業(調べる、ファイルを読み書きする、コードを書く、テストを実行する)は、できるだけ軽いモデルのサブエージェントに任せ、司令塔は判断・統合・ユーザーへの報告に専念する

## 担当の分担
| プロセス | 司令塔 | サブエージェント |
|---|---|---|
| プロセス1 入力整理 | 結果の確認 | 長い入力の整理(軽量) |
| プロセス2-1 DLPFC | ゴール・必要条件を決める(会話の文脈が必要なため、司令塔自身が行う) | なし |
| プロセス2-2 ACC | 努力量の判定 | なし |
| プロセス3 DLPFC・海馬 | 評価と、差し戻しの判断 | 海馬・ネットの調査(調査用) |
| プロセス4-1 行動候補生成 | 候補の確認 | 候補の書き出し(計画用) |
| プロセス4-2 行動決定 | 評価・選択・ユーザーへの提示 | なし |
| プロセス5 行動 | 指示文の作成と、報告の受け取り | 実装・レビュー |
| プロセス6 結果観察 | 必要条件の判定 | 変更ファイルの確認・テストの実行(軽量〜標準) |
| プロセス7 反省・記憶更新 | 原因の考察 | 活動報告・既知パターン・教訓ファイルの書き込み(軽量) |

## 手順
1. ユーザーの入力を受け取ったら、その入力に対応する活動報告があるか確認する
   - 場所: 有起点の活動報告のフォルダ(`meeting-room/activities/Trigger/YYYY-MM-DD-activities/`)
   - ない場合: その日のフォルダ内で最も大きい番号に1を足した番号(フォルダがなければ1)で、`meeting-room/activities/TEMPLATE.md` をもとに新規作成する(書き方は `3-Hippocampus/1-External_Hippocampus/` の `activity-report-rules.md` に従う)。依頼の題名は、プロセス1で依頼を整理したあとに、ファイル名に付ける
   - ある場合: その活動報告を更新していく
2. プロセス1から順に、各プロセスの手順書に従って進める
   - Geneが指定されているときは、各プロセスで、`2-DNAs/` のそのGeneの手順にも従う
   - プロセス3で差し戻しになったときは、プロセス3の指示に従って プロセス2-1またはプロセス2-2に戻る(差し戻しが3回を超えたら、ユーザーに相談する)
3. 各プロセスが終わるごとに、次の2つを行う
   1. ユーザーに報告する(下の「報告する内容」を参照)
   2. 活動報告の「実施内容」に、終えたプロセスを追記する
4. ユーザーの承認が必要なところ(プロセス4-2のファイルの位置説明・ファイルの手順説明の提示など)では、承認を得てから次に進む
5. プロセス7まで終えたら、活動報告を完成させ、ユーザーに最終報告をする

## 報告する内容
| プロセス | 報告する内容 |
|---|---|
| プロセス1 入力整理 | 整理した依頼の一覧と、「要確認」の有無、開始時のトークンの状態 |
| プロセス2-1 DLPFC | ゴール・必要条件 |
| プロセス2-2 ACC | 努力量(思考量の目安・海馬/ネット検索の深さ・モデル/サブエージェントの種類) |
| プロセス3 DLPFC・海馬 | ゴール・必要条件と努力量の評価結果(OKか、プロセス2-1またはプロセス2-2への差し戻しか)と、不確実な点 |
| プロセス4-1 行動候補生成 | 行動候補 |
| プロセス4-2 行動決定 | 選んだ行動とその理由、ファイルの位置説明、ファイルの手順説明(ここでユーザーの承認を得る) |
| プロセス5 行動 | 実行したことと、Issueのstatus |
| プロセス6 結果観察 | 必要条件ごとの判定とゴールの実現、テスト結果、アンケートの結果、予測とのずれ、トークンの状態 |
| プロセス7 反省・記憶更新 | 反省と、活動報告に記録した内容 |

## 注意
- 報告は短く、決まったことと次に進むプロセスが分かるようにする
- 活動報告への追記は、終えたプロセスと決まったことを1〜2行で書き、トークン消費を抑える
- 満たしていない必要条件やテストの失敗は、隠さずに伝える(テストが失敗したときは、その出力も伝える)
- トークン上限が近いときは、作業の続きより引き継ぎの活動報告を優先する(プロセス6を参照)
- このプロジェクトと関係ない他のプロジェクトの仕事は始めない
