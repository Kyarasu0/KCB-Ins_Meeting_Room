# プロセス6. 一次視覚野(Primary Visual Cortex)・視床下部(Hypothalamus): 結果観察
## 目的
- 行動の結果を、深い反省はせず、起きた事実の確認に集中して観察し、必要条件を満たしたかを判断する
- トークン上限が近づいていないかを確認し、近いときは作業の続きより引き継ぎを優先する

## 役割
- 行動の結果を観察し、必要条件を満たしたかを確認する(一次視覚野)
- 深い反省はせず、起きた事実の確認に集中する
- 状態(トークン残量など)を確認する(視床下部)

## 手順
1. プロセス5から受け取ったサブエージェントの報告を読む
2. 報告を鵜呑みにせず、変更されたファイルやテスト結果を実際に確認する
   - 確認とテストの実行は、軽量〜標準モデルのサブエージェントに任せ、判定は司令塔が行う
   - コードを変更・追加したら、関連するテストを必ず実行する(テストは開発対象のプロジェクト側にある。対象にテストが無いときは、その旨を報告し、動作確認の方法を代わりに示す)
   - テストが失敗したら、テストや必要条件を緩めて通さず、原因を報告する
3. 必要条件ごとに「満たした / 満たしていない」を判定する
4. プロセス4-2で活動報告に追記した予測結果と実際の結果を比べ、ずれ(予測誤差)を書き出す
5. 状態を確認する
   - 下の「トークン上限が近いとき」に当てはまらないか確認する
6. 結果をプロセス7(反省・記憶更新)に渡す

## トークン上限が近いとき
### 判断の合図
- ユーザーから「残り少ない」「もう少しで上限」などと伝えられた
- 会話が長くなり、コンテキストの使用量が70〜80%に近づいてきた

### やること(作業の続きより先に行う)
1. 今の作業を安全な区切りで止める
2. 引き継ぎ用の活動報告を書く
   - やったこと・やっていないこと・次にやるべきことを具体的に書く
   - 途中の手順があれば、どこまで進んだかを書く
3. 余裕があれば、コミットとpushを行いPRを出す(`2-Hippocampus/1-External_Hippocampus/` の `activity-report-rules.md` の「トークン上限が近いとき」を参照)
4. 残りのトークンで作業を続けられそうなら、続きを行う

## プロセス7への引き渡し内容
- 必要条件ごとの判定(満たした / 満たしていない)
- 予測とのずれ(予測誤差)
- テスト結果
