# プロセス6. 一次視覚野(Primary Visual Cortex)・視床下部(Hypothalamus)・腹側被蓋野(VTA): 結果観察
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 予測誤差 | プロセス4-2で予測したものと、実際とのずれ。結果の予測誤差(予測した結果と実際の結果のずれ)と、報酬の予測誤差(実際のドーパミンスコア − 予測のドーパミンスコア)がある。報酬・ドーパミンスコアは、プロセス4-2の用語の説明を参照する |
| アンケート | ユーザーに、「どのくらい満足しているか」を数値(1〜10など)で聞き、あわせて、Claudeの今後の改善のためにフィードバックとして聞きたいことを聞くもの。聞く内容は、その都度適切なものを考える |
| トークン消費の目安 | ユーザーに聞いた5時間リセット・ウィークリーリセットの残り%の減り方と、その間にClaudeが消費した具体的なトークン量から分かる、「このくらいのトークンで何%減る」という目安。5時間リセット・ウィークリーリセットは、プロセス1の用語の説明を参照する |

## 目的
- 出来上がった全体の結果を調査し、品質の検査やルールへの則り、シンプルさの担保、テスト通過率などを調べ、作業の結果としての情報を収集する
- 必要条件をすべて満たして、ゴールを実現できたかを確認する
- ユーザーの満足度とフィードバックをアンケートで聞き、実際のドーパミンスコアを採点し、プロセス4-2の予測とのずれ(予測誤差)を書き出す
- トークン消費を記録して、トークン消費の目安を作り、トークン上限が近づいていないかを確認する。近いときは作業の続きより引き継ぎを優先する

## 役割
- 行動の結果を観察し、必要条件を満たして、ゴールを実現できたかを確認する。ユーザーの反応も観察する(一次視覚野)
- 実際のドーパミンスコアを出し(ドーパミンの分泌にあたる)、予測とのずれ(報酬の予測誤差)を出す(腹側被蓋野)
- 深い反省はせず、起きた事実の確認に集中する
- トークンの状態(5時間リセット・ウィークリーリセットの残り%、Claudeの消費量)を確認して、`4-Hypothalamus/` に記録する(視床下部)

## 手順
1. プロセス5から受け取ったサブエージェントの報告を読む
2. 報告を鵜呑みにせず、出来上がった全体の結果を実際に調査する(変更されたファイルやテスト結果)
   - 品質の検査、ルール(`3-Hippocampus/1-External_Hippocampus/` の `user-rules.md` や、meeting-roomの固有のルールなど)への則り、シンプルさの担保、テスト通過率などを調べる
   - 調査とテストの実行は、軽量〜標準モデルのサブエージェントに任せ、判定は司令塔が行う
   - コードを変更・追加したら、関連するテストを必ず実行する(テストは開発対象のプロジェクト側にある。対象にテストが無いときは、その旨を報告し、動作確認の方法を代わりに示す)
   - テストが失敗したら、テストや必要条件を緩めて通さず、原因を報告する
3. 必要条件ごとに「満たした / 満たしていない」を判定し、すべて満たしたことでゴールを実現できたかも判定する
4. ユーザーに結果を報告し、次の3つを行って、活動報告に記録する
   - アンケート: 満足度と、今後の改善のために聞きたいことを、ユーザーに聞く
   - 実際のドーパミンスコア: ユーザーの反応とアンケートの回答から、ドーパミンスコア(1〜10、理由付き)で採点する。ユーザーに確認を取ってから、そのスコアを記録する(腹側被蓋野)
   - トークンの状態: 5時間リセットとウィークリーリセットの残りトークンの%をユーザーに聞き、`4-Hypothalamus/` の `Token_Usage.md` を更新する(視床下部)
   - ユーザーが全く他の話をしたときは、聞く内容の保留(プロセス1の用語の説明を参照)をして、次の依頼・作業に進む。保留中の項目は、ユーザーが手の空いていそうなときに、もう一度聞く
5. プロセス4-2で活動報告の「プラン」に書いた予測した結果・予測のドーパミンスコアと、実際の結果・実際のドーパミンスコアを比べ、予測誤差(結果と報酬)を書き出す(腹側被蓋野)
6. トークン消費の目安を更新する
   - プロセス1で聞いた開始時の%と今回の%の差、その間にClaudeが消費した具体的なトークン量から、どのくらい使うとどのくらい%が減るかを計算し、`Token_Usage.md` の目安を更新する
7. 状態を確認する
   - 下の「トークン上限が近いとき」に当てはまらないか確認する
8. 結果をプロセス7(反省・記憶更新)に渡す

## トークン上限が近いとき
### 判断の合図
- ユーザーから「残り少ない」「もう少しで上限」などと伝えられた
- 5時間リセットまたはウィークリーリセットの残りトークンが、20〜30%を切った(トークン消費の目安から、今の作業を終えるまでに足りるかも判断する)

### やること(作業の続きより先に行う)
1. 今の作業を安全な区切りで止める
2. 引き継ぎ用の活動報告を書く
   - やったこと・やっていないこと・次にやるべきことを具体的に書く
   - 途中の手順があれば、どこまで進んだかを書く
3. 余裕があれば、コミットとpushを行いPRを出す(`3-Hippocampus/1-External_Hippocampus/` の `activity-report-rules.md` の「トークン上限が近いとき」を参照)
4. 残りのトークンで作業を続けられそうなら、続きを行う

## プロセス7への引き渡し内容
- 必要条件ごとの判定(満たした / 満たしていない)と、ゴールを実現できたか
- 調査の結果(品質・ルールへの則り・シンプルさ・テスト通過率など)
- アンケートの結果と、実際のドーパミンスコア(理由付き)
- 予測誤差
- トークンの状態と、トークン消費の目安
- テスト結果
