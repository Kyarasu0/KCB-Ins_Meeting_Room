# プロセス5. 一次運動野(Primary Motor Cortex): 行動
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 既存の計画 | Issueに書かれた計画や、ユーザーに渡された計画。プロセス4-2で承認されたプランと同じように、そのまま実行できる |

## 目的
- プロセス4-2で承認された行動、または既存の計画を、具体的な作業としてサブエージェントに実行させる
- GitHub IssuesやLinearなどのIssue管理ツールを使っている場合は、Claudeの起動時(ユーザーの入力時)に、このプロジェクトのフォルダのIssueもあわせて確認する。「request-claude」タグが付いているIssueは、次のルールで作業を開始する
   1. Assigneeを、Claudeを動かしているアカウントにする
   2. 先に他の人が割り当てられているときは、作業を横取りしない
   3. 「request-claude」タグが外れたら、すぐに作業を中止する
   4. statusは、作業の進み具合に合わせてこまめに変更する
- 既存の計画をそのまま実行するだけなら、このプロセスから始めてよい
- このプロジェクトと関係ない、他のプロジェクトの仕事は始めない

## 役割
- 選んだ行動、または既存の計画を、具体的な作業としてサブエージェントに実行させる
- Issue管理ツールを使っている場合は、Issueの割り当て・タグ・statusを管理しながら作業する
- Issueが複数あるときは、互いに干渉しないものを同時に着手する。先にやるべきことがあるIssue(blocked)は、前提のIssueが終わってから着手し、着手するときに「blocked」を外す

## 手順
1. Issue管理ツールを使っている場合は、「request-claude」タグが付いたIssueを確認し、「目的」のルールに従って作業を開始する(既存の計画の実行は、ここから始めてよい)
2. プロセス4-2で承認されたプラン、または既存の計画を、サブエージェントへの指示文にする
   - プロセス2-2から直接渡されたとき(プロセスを飛ばしたとき)は、ゴール・必要条件と努力量をもとに、指示文を作る
3. 使うモデル・種類でサブエージェントを起動する(プロセス4-2で選んだ行動に書かれたもの。プロセス2-2から直接渡されたときは、プロセス2-2で決めたもの)
   - 互いに依存しない作業は並列で起動する
   - 同じファイルを複数のサブエージェントに同時に編集させない
   - 互いに干渉しないIssueは、同時に着手してよい。先にやるべきことがあるIssueは「blocked」にしておく
4. 作業の進み具合に合わせて、Issueのstatusを変更する。「request-claude」タグが外れていたら、すぐに作業を中止する
5. サブエージェントの報告を受け取る
6. 報告を プロセス6(結果観察)に渡す

## コード作成のときのサブエージェントの分け方
| 役割 | 種類・モデルの目安 | 内容 |
|---|---|---|
| 実装 | 汎用 / 標準(難しければ高性能) | 承認されたプランの手順どおりにコードを書く |
| レビュー | 実装とは別のサブエージェント / 標準 | 結果とプランの必要条件を照らし合わせて確認 |

- 調べものは プロセス3の記憶統合で済ませる。プロセス5では基本的に調査をしない(足りないときは プロセス3に戻る)
- 実装は、互いに依存しないファイルのまとまりごとに分けて並列にする
  - 同じファイルは1つのサブエージェントだけが編集する
  - 依存があるものは、依存される側から順番に実装する
- 1つのサブエージェントには、完了条件を1つだけ持たせる
- 実装したサブエージェント自身に「できた」と判定させず、テストは プロセス6で、レビューは別のサブエージェントで行う

## サブエージェントへの指示文に必ず含めるもの
- ゴールと、その作業で満たすべき必要条件
- 承認されたプラン(ファイルの位置説明・ファイルの手順説明)
- プロセス3で調べた結果(根拠・変更箇所・似た既存コードなど)
- 対象のファイルパス(分かっていれば)
- 守るべきルール(`2-Hippocampus/1-External_Hippocampus/` の `user-rules.md` の書き方など。コードを書くときは、ファイルの手順説明をコード内のコメントとして書く)
- やってはいけないこと(例: 外部海馬は編集しない、pushしない)
- 報告してほしい内容(変更したファイル、困ったこと)

## 注意
- サブエージェントの報告はユーザーには直接見えない。司令塔が必要な内容をまとめてユーザーに伝える
- サブエージェントが失敗を繰り返す場合は、固執せず プロセス3に戻って見直す
- Issueの割り当てが他の人にあるときは、作業を横取りしない
- このプロジェクトと関係ない他のプロジェクトの仕事は始めない。Issueやタグを見つけても、このプロジェクトのものかを確認してから始める

## プロセス6への引き渡し内容
- ゴール・必要条件
- 実行した行動と、サブエージェントの報告(変更したファイル、困ったこと)
- プロセス4-2で予測した結果
- Issueのstatus(あれば)
