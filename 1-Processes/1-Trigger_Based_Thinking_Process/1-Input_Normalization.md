# プロセス1. 連合皮質(Association Cortex)・視床下部(Hypothalamus): 入力整理
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 5時間リセット | Claudeの利用上限のうち、5時間ごとにリセットされるもの。ユーザーに、その残りトークンの%を聞く |
| ウィークリーリセット | Claudeの利用上限のうち、1週間ごとにリセットされるもの。ユーザーに、その残りトークンの%を聞く |
| 聞く内容の保留 | トークンの残り%やアンケートなどをユーザーに聞いたとき、ユーザーが全く他の話をした場合は、その質問を一旦保留(無視)して、次の依頼・作業に取り掛かること。ユーザーが手の空いていそうなときに、もう一度聞く。プロセス6でも同じ |

## 目的
ユーザーの冗長な入力を整理し、以降のプロセスで動くエージェントが入力を読んで考える際のトークン消費を抑える。
意味が曖昧な箇所は勝手に解釈するのではなく、このプロセスの時点で聞き返して、解決しておく。
あわせて、作業を始める時点のトークンの状態を記録し、プロセス6でトークン消費の目安を作れるようにする。

## 役割
- ユーザーの入力を、**網羅率100%**のまま、**重複**や**言い換え**などの冗長をなくして整理する(連合皮質)
- 作業を始める時点のトークンの状態を、ユーザーに聞いて記録する(視床下部)

## 手順
1. 新しい作業を始めるときは、5時間リセットとウィークリーリセットの残りトークンの%をユーザーに聞き、`4-Hypothalamus/` の `Token_Usage.md` に記録する
   - ユーザーが全く他の話をしたときは、聞く内容の保留をして、次の依頼・作業に進む
2. 入力が短い(2〜3文程度)なら整理せず、そのまま次のプロセスに渡す
3. 長い入力は、軽量モデルのサブエージェントに渡し、依頼を1つずつ箇条書きに分けさせる
4. 重複・言い換えをまとめ、各依頼が元の入力のどこに当たるかを対応づける。元の入力の文すべてが、どれかの依頼に対応していること(網羅率100%)を確認する
5. 意味が曖昧な箇所は、勝手に解釈せず「要確認」としてユーザーに確認する
6. 整理結果を次のプロセスに渡す

## サブエージェントへの指示文の例
```text
以下のユーザー入力を、依頼ごとの箇条書きに整理してください。
- 元の入力の内容を1つも落とさないこと
- 同じ内容の繰り返しや言い換えは1つにまとめること
- 各依頼の後ろに、元の入力の該当部分を「」で引用すること
- 意味が曖昧な箇所は「要確認」として理由と一緒に書くこと
- 解釈や提案は加えないこと
```
