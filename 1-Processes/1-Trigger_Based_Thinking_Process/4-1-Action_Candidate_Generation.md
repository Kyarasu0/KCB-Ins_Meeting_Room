# プロセス4-1. 背外側前頭前皮質(DLPFC): 行動候補生成
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 行動候補 | ゴール・必要条件を満たすための行動の案。1つの行動候補は複数のステップからなる |
| ステップ | 行動の最小単位(例: 今いるフォルダを確認する、.gitがあるか確認する)。ゴール・必要条件から逆算して組み立てる。Claudeは単純な作業ならステップに分けなくてもこなせるため、ステップに分けるのは複雑な場合のみでよい |
| ファイルの位置説明 | 編集するファイルがどのフォルダにあるかをtree形式で示し、各フォルダ・各ファイルが何かを1文で解説したもの。新規・変更・削除・名前変更のどれかも明記する |
| ファイルの手順説明 | 各ファイル内で行う処理を、処理の塊ごとに1., 2., 3.…の手順で書いたもの |

## 目的
- 決定した1つのゴールとそれに対応する必要条件に対して、1通りではなく複数の行動候補を考案し、他の選択肢がある中でなぜその行動が最適かを考えたうえで行動できるようにする
- 努力量が小さいときや、ゴールへの過程において明らかに最良の1通りが存在すると判断できるときは、行動候補を複数生成しなくてよい

## 役割
- ゴールと必要条件を保持したまま、取り得る行動候補を複数列挙する
- 複雑な場合は、各行動候補を、ゴール・必要条件から逆算したステップに分ける

## 手順
1. プロセス3(2回目のDLPFC)から受け取ったゴールと必要条件を確認する
2. 必要条件をすべて満たせる行動候補を**2〜4個**列挙する
   - 努力量が小さいときや、明らかに最良の1通りがあるときは、候補は1つだけでよい(その場合、比較は省略する)
3. 各候補が複雑な場合は、ステップに分ける
   - 必要条件を満たした状態から逆算して、その直前に必要なステップを順にさかのぼり、実行する順に並べる
   - 各ステップは行動の最小単位にする
   - 単純な作業なら、ステップに分けず、候補の概要だけ書けばよい
4. 各候補について、以下を書く
   - ステップ(分けた場合は、各ステップで何をするか(1〜2文))
   - どの必要条件をどう満たすか
   - 実行に使うサブエージェントの種類とモデル
   - 変更するファイル(あれば)。ファイルを作成・変更する候補では、ファイルの位置説明とファイルの手順説明も書く
   - ファイルの位置説明は、プロダクトのREADMEやmeeting-roomのファイル構成に書かれていればそれを使う。書かれていなければ、実際にフォルダ・ファイルの中身を確認して書く(推測で書かない)
5. ゴール・必要条件(プロセス2-1)、努力量(プロセス2-2)、候補一覧(それぞれ複数のステップを持つ)を、プロセス4-2(行動決定)に渡す

## 候補の出し方のコツ
- 「最小限の変更で済む案」と「根本的に解決する案」を両方出すと比較しやすい
- ユーザーが以前に好んだやり方が内部海馬にあれば、それを候補に含める
- ユーザーに確認が必要な操作(削除・push・外部への送信など)を含む候補には、その旨を明記する

## プロセス4-2への引き渡し内容
- プロセス2-1(1回目のDLPFC)で決めたゴール・必要条件
- プロセス2-2(ACC)で決めた努力量
- 行動候補の一覧(それぞれ複数のステップを持つ。候補ごとのステップ・満たす必要条件・サブエージェントとモデル・変更するファイル(ファイルの位置説明・ファイルの手順説明を含む))
