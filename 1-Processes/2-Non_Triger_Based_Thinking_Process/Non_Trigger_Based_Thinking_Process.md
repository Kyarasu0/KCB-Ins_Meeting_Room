# 無起点思考プロセス. 視床下部(Hypothalamus)・海馬(Hippocampus): ユーザーの入力がないときの思考
## 用語の説明
| 用語 | 説明 |
| --- | --- |
| 無起点思考 | ユーザーの入力なしに、定期実行(クラウドのルーティンやcronなど)で起動されて行う思考。テーマを1つ決めたら、そのテーマを依頼として、有起点思考プロセス(`1-Trigger_Based_Thinking_Process/`)で行う。普通の入力には、有起点思考をそのまま使う |
| テーマ | 無起点思考で1回の起動につき1つだけ行うこと。睡眠・自己向上・反省のどれか |

## 目的
- ユーザーの入力がないときにも、内部海馬を整理し、次の有起点思考に役立つ知識や反省を蓄える
- 使うのは、ユーザーが「無起点で動いて」と指定したときか、定期実行の指示文に書かれているときだけにする

## 役割
- 1回の起動で、テーマを1つだけ選んで実行し、結果を記録する
- 内部の状態(睡眠の必要性、トークンの状態)を評価して、テーマを選ぶ(視床下部)
- 選んだテーマを依頼として、有起点思考プロセス(プロセス1〜7)で行う。睡眠だけは、睡眠プロセスを行う
- ユーザーに確認できないため、外部への変更はしない(deskの活動報告への記録は例外。睡眠では、KCBの記憶への登録も例外)

## テーマ
| テーマ | 内容 |
|---|---|
| 睡眠 | `3-Sleep_Process/` のNREM睡眠・REM睡眠を、下の制限つきで実行する |
| 自己向上 | 自分だけでなく、ユーザーの向上も狙って、調べたり考えたりする。対象は、下の「自己向上の対象」から選ぶ |
| 反省 | 過去の活動報告を読み、何回も間違えていることや、何回も指摘されていることを選別して、教訓として活動報告に書く |

## テーマの選び方
上から順に判定し、最初に当てはまったものを選ぶ。選んだ理由は、活動報告に書く
1. 睡眠: 睡眠が必要な条件に当てはまる(`3-Sleep_Process/1-NREM_Sleep_Process/` の「睡眠が必要だと判断する条件」を参照)
2. 履歴が空: 自己向上
3. 強制: 直近4回で選ばれていないテーマがあれば、それを選ぶ
4. 前倒し: 直近の活動報告で、ゴールを実現できていなかったり、ドーパミンスコアが低かったり、エラーがあったときは反省を選ぶ(連続2回まで)
5. 不足: 直近10回の履歴で、自己向上6 : 反省4の割合に足りないほうを選ぶ

- 履歴は、deskの無起点の活動報告(冒頭のテーマ名と結果)から読む
- 上の割合・回数は、プロジェクトごとに変えてよい

## 手順
### 1. 内部状態の評価(視床下部)
1. deskの無起点の活動報告から、直近10回の履歴(テーマ・選んだ理由・結果)を読む
2. deskの有起点・無起点の活動報告のうち、`_reviewed` が付いていないものの数を数えて、睡眠が必要かを判定する(条件は、NREM睡眠の手順書を参照)
3. `4-Hypothalamus/` の `Token_Usage.md` の記録と「トークン消費の目安」を見て、直近の残りが少ない(20〜30%を切っていた)ときは、実行せず、活動報告に書く
4. 上の「テーマの選び方」で、今回のテーマを1つ決める

### 2. テーマの実行
- 睡眠
  1. NREM睡眠、REM睡眠の順に行う(それぞれの手順書に従う)
  2. NREM睡眠のブランチの片付けは、ユーザーの確認が取れないため行わない
  3. 片付けが必要そうなものは、活動報告の「未解決」に書き残す
- 自己向上・反省: 決めたテーマを依頼として、有起点思考プロセスで行う。プロセスごとの違いは、次のとおり
  1. プロセス1: テーマを1つの依頼として扱う。ユーザーに聞く内容(トークンの残り%)は、聞かない
  2. プロセス2-1〜4-1: テーマのゴール・必要条件を決め、調べる。努力量は、「モデルの選び方」に従う
  3. プロセス4-2: ファイルの作成・変更を伴う行動(deskの活動報告への記録を除く)はしないため、ユーザーへのプラン提示と承認は行わない
  4. プロセス5: 調査や考察を、サブエージェントに任せる
  5. プロセス6: ユーザーに聞く内容(アンケート、ドーパミンスコア、トークンの残り%)は、聞かない。Claudeが消費したトークン量は、記録する
  6. プロセス7: 反省・記憶更新を行う。ただし、「反省の手順」で選別したもの以外は、教訓として記録しない

#### 自己向上の対象
1回の起動で、次から1つ選ぶ
| 対象 | 内容 |
|---|---|
| ユーザーの向上 | ユーザーの役に立ちそうな知識や気づきを調べるだけでなく、Claudeがユーザーにどう役に立ちそうかも考えて、ユーザーに連絡する(例: ネットでは、こんなふうにClaudeを使っている人もいるらしい、という提案) |
| DNAで指定されている調査 | `2-DNAs/` のDNAで指定されている調査を行う |
| コードのリファクタリング | プロダクトのコードを読んで、リファクタリングについて考える(考えるだけで、コードは変更しない)。結果は、ユーザーに連絡する |
| クラウドAIのスキル | ネットで、クラウドAIのスキルについて調べる |
| 思考プロセスの提案 | この思考プロセスについて、特に良い点や、改善してもよいかもしれない点を提案する |

#### 自己向上の手順
1. KCBの海馬(内部海馬と外部海馬)と、deskを検索する(外部海馬が優先)
2. Web検索を、1回の起動につき多くても3回まで行う
3. 対象を1つ決め、調べて要点をまとめる
4. 次に探索したい対象を1つ生成し、今回の無起点の活動報告の「次の自己向上の候補」に書く

#### 反省の手順
1. 過去の出来事(有起点の活動報告)を1〜3件選んで読む(予測誤差が大きかったもの、ドーパミンスコアが低かったものを優先する)
2. 読んだ活動報告のうち、何回も間違えていること、何回も指摘されていることだけを選別する(過去の活動報告や Experiences に、同じ内容がすでにあるかも確認する。毎回、何かを見つけようとはしない)
3. 選別したものだけを、今回の活動報告に、教訓として書く(Experiences や `generalized-knowledge.md` への登録は、睡眠で行う)
4. 選別したものがなければ、何も記録せず、その旨を活動報告に書く

### 3. 記録と通知
1. 無起点の活動報告(`desk/activities/Non_Trigger/YYYY-MM-DD-activities/YYYY-MM-DD-N.md`。用語はオーケストレーターの用語の説明を参照)を、`desk/activities/TEMPLATE.md` の形で書く。冒頭に「無起点・テーマ名」と書く
2. 活動報告に、テーマ・選んだ理由・結果も書く(次回以降の履歴として読まれる)
3. 残りトークン量が確認できるときは、Claudeが消費したトークン量を、`Token_Usage.md` に記録する(ユーザーに残り%は聞けないため、その欄は空にして、備考に「無起点」と書く)
4. 通知の方法がある場合は、ユーザーに連絡する内容(ユーザーの向上、リファクタリングの考察、思考プロセスの提案など)を、複数回分をまとめて通知する(1回ごとには通知しない)

## やってはいけないこと
- 外部への変更をしない(ファイルの上書き・削除、権限の変更、購入、発注、送金、外部サービスへの書き込み)。ただし、deskの活動報告への記録は例外とする(睡眠では、KCBの記憶への登録も例外とする)
- 外部海馬(ユーザーの資料)を変更しない
- 書き込んでよいのは、deskの活動報告、KCBの記憶(睡眠のときだけ)、`Token_Usage.md`、ユーザーへの通知だけにする。それ以外には書き込まない
- 迷ったら、実行せずに「ユーザーに確認が必要」と活動報告に書く

## モデルの選び方(トークンの節約)
- 無起点の1回は、プロセス2-2の「努力量の判定基準」で、原則として「小」〜「中」で足りるものにする
- 作業は、サブエージェントに割り振る。司令塔は、判断と統合と記録だけをする
- 「特大」が必要そうなときは、実行せず、ユーザーへの確認事項として残す
